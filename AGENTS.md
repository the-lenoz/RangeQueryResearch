# Спецификация RangeQueryResearch

## Назначение

Сравнить реализации динамического множества с поддержкой порядковой статистики. Исполняемый файл читает поток команд, запускает выбранную структуру данных и выводит результаты запросов.

## Контракт предметной области

Множество содержит уникальные ключи типа `int` со знаком.

| Команда | Значение |
| --- | --- |
| `k x` | Вставить `x`; повторная вставка существующего ключа ничего не меняет. |
| `q l r` | Вернуть количество ключей в интервале `(l, r]`. |
| `m i` | Вернуть `i`-й по величине ключ, где `i` начинается с единицы. |
| `n x` | Вернуть количество ключей, строго меньших `x`. |

Политика обработки некорректного `m i`, повреждённого ввода и аргументов командной строки в этом каркасе пока не выбрана и должна быть согласована до реализации.

## Контракты модулей

`rangequery.config` отвечает за конфигурацию CLI. Он сопоставляет `--structure` со значением `rq::StructureKind`; функция `read_command_line` не должна выполнять ввод-вывод и получает только аргументы командной строки.

`rangequery.structures.contracts` задаёт общую семантику. `select` использует индексацию с единицы и возвращает `Selection{.has_value = false}`, если индекс недопустим. `count_in_open_closed_range(left, right)` реализует `(left, right]` и возвращает ноль при `left >= right`.

`rangequery.structures.ordered_vector` поддерживает отсортированное непрерывное хранилище.

`rangequery.structures.std_set` является базовой реализацией на стандартной библиотеке. Её операции ранжирования и выбора могут быть линейными, поскольку `std::set` не хранит размеры поддеревьев.

`rangequery.structures.avl` является AVL-деревом, дополненным размерами поддеревьев; сложность операций имеет логарифмическую верхнюю границу.

В первой реализации присутствуют `ordered_vector`, `std_set`, `avl` и `treap`. Они используют структурный API и выбираются во время выполнения через `std::variant`; виртуальное наследование не применяется. Treap хранит случайные приоритеты и размеры поддеревьев; его сложность ожидаемо логарифмическая.

## Правила размещения

Весь рабочий код находится в `src/`. Модуль с единицей реализации располагается в отдельном каталоге; модуль, состоящий только из интерфейсной единицы, может находиться непосредственно в `src/`. Тесты находятся в `tests/`, скрипты автоматизации — в `tools/`, воспроизводимый визуальный анализ — в `notebooks/`.

## Контракт проверки

Каждая структура должна проходить одинаковые поведенческие тесты. Тесты должны проверять повторные вставки, отрицательные границы, предельные значения `int`, пустые структуры, недопустимый выбор и все четыре команды. Бенчмарки должны записывать распределение входа, seed, конфигурацию компилятора и сборки, число операций и время каждого запуска.
