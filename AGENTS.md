# Спецификация RangeQueryResearch

## Назначение

Сравнить реализации динамического множества с поддержкой порядковой статистики. Исполняемый файл читает поток команд, запускает выбранную структуру данных и выводит результаты запросов.

## Контракт предметной области

Множество содержит уникальные ключи типа `int` со знаком.

| Команда | Значение |
| --- | --- |
| `k x` | Вставить `x`; повторная вставка существующего ключа ничего не меняет. |
| `q l r` | Вернуть количество ключей в интервале `(l, r]`. |
| `m i` | Вернуть `i`-й по величине ключ, где `i` начинается с единицы. |
| `n x` | Вернуть количество ключей, строго меньших `x`. |

Некорректный `m i`, повреждённый ввод и ошибки аргументов командной строки завершают соответствующий исполняемый файл с кодом 2 и диагностикой в stderr.

## Контракты модулей

`rangequery.structures.kind` определяет `rq::StructureKind` и `rq::to_string`. `rangequery.config` отвечает за конфигурацию CLI обоих исполняемых файлов и реэкспортирует `rangequery.structures.kind` для совместимости. CLI11 2.7.2 разбирает аргументы, сопоставляет `--structure` со значением `rq::StructureKind`, формирует help и диагностику. `read_command_line` возвращает `std::expected<Settings, int>`, `read_benchmark_command_line` — `std::expected<BenchmarkSettings, int>`. Значение означает успешный разбор; `unexpected` запрашивает раннее завершение с кодом 0 после help или 2 после ошибки. Соответствующий текст уже выведен CLI11 в stdout или stderr; вызывающий код не печатает его повторно. Поведение `-h`/`--help`, включая взаимодействие с ошибочными аргументами, определяется библиотекой без предварительного просмотра argv. Повторные одиночные параметры отклоняются; поддерживается форма `--name=value`. В основном приложении структура по умолчанию — `vector`. В benchmark обязательны `--structure` и `--mode` (`queries`, `insert`, `dynamic`); положительный `--setup-count` обязателен только в dynamic-режиме и запрещён в остальных режимах.

`rangequery.structures.contracts` задаёт общую семантику. `Selection` является alias для `std::optional<int>`; `select` использует индексацию с единицы и возвращает `std::nullopt`, если индекс недопустим. `count_in_open_closed_range(left, right)` реализует `(left, right]` и возвращает ноль при `left >= right`.

`rangequery.structures.factory` экспортирует общий `SelectedStructure` на основе `std::variant` и функцию `make_structure(StructureKind)`, возвращающую `std::expected<SelectedStructure, std::string_view>`. Неизвестное значение enum возвращает ошибку `unknown structure kind`.

Все четыре структуры непосредственно хранят состояние в приватных полях, без pimpl. Вспомогательные операции деревьев и вложенные типы узлов приватны; определения узлов и алгоритмов находятся в единицах реализации.

Все структуры имеют семантику значений: копирование создаёт независимую глубокую копию. Move constructor и перенос владения имеют константную сложность и не выбрасывают исключений; move assignment дополнительно уничтожает прежнее состояние целевого объекта. Объект после перемещения эквивалентен пустому множеству, остаётся пригоден для всех запросов и может снова принимать вставки.

`rangequery.structures.ordered_vector` поддерживает отсортированное непрерывное хранилище.

`rangequery.structures.std_set` является базовой реализацией на стандартной библиотеке. Её операции ранжирования и выбора могут быть линейными, поскольку `std::set` не хранит размеры поддеревьев.

`rangequery.structures.avl` является AVL-деревом, дополненным размерами поддеревьев; сложность операций имеет логарифмическую верхнюю границу.

В первой реализации присутствуют `ordered_vector`, `std_set`, `avl` и `treap`. Они используют структурный API и выбираются во время выполнения через общую variant-фабрику; виртуальное наследование не применяется. Treap хранит случайные приоритеты и размеры поддеревьев; его сложность ожидаемо логарифмическая. Приоритеты генерирует внутренний 8-байтный SplitMix64 с фиксированным seed `0x8e4d3b291f76a5c1`; состояние генератора участвует в семантике копирования, а повторная вставка не расходует случайное число.

## Правила размещения

Весь рабочий код находится в `src/`. Модуль с единицей реализации располагается в отдельном каталоге; модуль, состоящий только из интерфейсной единицы, может находиться непосредственно в `src/`. Тесты находятся в `tests/`, скрипты автоматизации — в `tools/`, воспроизводимый визуальный анализ — в `notebooks/`.

## Контракт проверки

Каждая структура должна проходить одинаковые поведенческие тесты. Тесты должны проверять повторные вставки, отрицательные границы, предельные значения `int`, пустые структуры, недопустимый выбор и все четыре команды.

Бенчмарки должны записывать распределение входа, фактически использованный seed, конфигурацию компилятора и сборки, число операций и время каждого запуска. `rangequery_benchmark` читает и разбирает workload до измерения. В query-сценариях подготовительные вставки выполняются вне таймера, а измеряются только `q`, `m` и `n`; в insert-сценариях измеряются все `k`. В dynamic-сценариях число setup-вставок передаётся явно, они выполняются вне таймера, а следующая за ними фаза с произвольным чередованием `k`, `q`, `m` и `n` измеряется целиком. Запуск и завершение процесса, parsing, stdin/stdout, setup, validation и форматирование результата не входят в operation wall time. Каждый запуск обязан пройти независимую последовательную checksum-проверку в Python до записи строки CSV; для dynamic-потока она проверяет ответы в состоянии на момент запроса и итоговое множество.
