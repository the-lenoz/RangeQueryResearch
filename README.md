# RangeQueryResearch

Исследовательский проект на C++23 для сравнения реализаций динамического множества с поддержкой порядковой статистики.

## Сборка

```sh
cmake --preset debug
cmake --build --preset debug
ctest --preset debug
```

Доступны пресеты `debug` для разработки и `release` для бенчмарков. Оба используют Ninja и создают изолированные каталоги `build/<preset>`.

Проект требует CMake 3.28 или новее и компилятор с поддержкой сканирования зависимостей C++ modules. Текущая конфигурация проверена с GCC 16 и CMake 4.4.

## Структура проекта

- `src/` — модули C++ и исполняемый файл CLI `rangequery`;
- `tests/` — поведенческие тесты и тесты контрактов на GoogleTest;
- `tools/` — детерминированный генератор payload и запускатель бенчмарков;
- `notebooks/benchmark_results.ipynb` — воспроизводимый анализ результатов бенчмарков;
- `AGENTS.md` — актуальные контракты и правила размещения проекта.

Исполняемый файл поддерживает `vector`, `set` и `avl`. Все реализации предоставляют одинаковый структурный API и выбираются во время выполнения через `std::variant`; виртуальное наследование не используется.

## Бенчмарки

Для асимптотических графиков используется размер множества `data_size`, а не длина потока команд. Каждый workload сначала вставляет ровно `data_size` уникальных ключей, затем выполняет фиксированное число `query_count` запросов (по умолчанию 10 000). Это отделяет влияние размера структуры от длины потока запросов.

```sh
python3 tools/benchmark.py \
  --binary build/release/src/rangequery \
  --output benchmark-results/scaling.csv \
  --data-sizes 1000 3000 10000
```

Для проверки локальности обращений используются одинаковые множества среднего размера и большое количество запросов; `hotspot` концентрирует их вокруг центральных 5 % ключей.

```sh
python3 tools/benchmark.py \
  --binary build/release/src/rangequery \
  --output benchmark-results/locality.csv \
  --data-sizes 1000 3000 10000 \
  --query-count 100000 \
  --query-kind rank \
  --localities uniform hotspot
```

CSV содержит `data_size`, `query_count`, общее число команд `command_count`, локальность, тип запроса, конфигурацию запуска и время. Поле `ns_per_query` удобно для сравнения скорости запросов между сценариями с одинаковым `query_count`.
